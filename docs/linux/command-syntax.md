# 命令的语法骨架

## 它是什么

Linux 命令不是一堆要靠死记硬背的单词，而是一门有语法的语言。翻遍几百个命令，绝大多数都长同一个样子：

```text
命令  [选项]  [参数]
  │      │        └─ 操作的对象：文件、目录、一段字符串
  │      └─ 开关，改变命令的行为
  └─ 一个程序的名字
```

理解了这个骨架，学新命令就只剩"查它有哪些选项"一件事。

## 拆一条出来看

拿熟悉的命令当样本：

```bash
ls -lh /srv/models/
```

| 部分 | 是什么 | 说明 |
|---|---|---|
| `ls` | 命令 | 一个可执行程序的名字 |
| `-lh` | 选项 | `-l` 长格式，`-h` 人类可读（把字节变 KB/MB/GB）。两个短选项可合并写 |
| `/srv/models/` | 参数 | 要列哪个目录 |

选项有两种写法，等价：

```bash
ls -lh /srv/models/              # 短选项：一个减号，可合并
ls --long --human-readable /srv/models/   # 长选项：两个减号，写全
```

短选项图快，长选项图好懂。写脚本时偏爱长选项——半年后回看，`--human-readable` 比 `-h` 清楚。

## 连接件：把命令拼成流水线

单条命令能力有限，真正的威力在于把它们接起来。四个连接件：

### 管道 `|`

把左边命令的**输出**，直接喂给右边命令当**输入**。数据像水流过管子。

```bash
ls -lh /srv/models/ | grep gguf
```

`ls` 列出所有东西，`grep` 从中筛出含 `gguf` 的行。一个负责"取"，一个负责"筛"。

### 重定向 `>` `>>` `2>`

默认情况下，输出打在屏幕上。重定向把它改道写进文件：

| 符号 | 作用 |
|---|---|
| `>` | 写进文件，**覆盖**原有内容 |
| `>>` | 追加到文件末尾 |
| `2>` | 只接**错误**输出（标准错误） |
| `&>` | 正常输出和错误一起接 |

```bash
# 把服务输出写进日志：正常和错误都导进去
nohup llama-server -m model.gguf > ~/logs/llama-server.log 2>&1 &
```

`2>&1` 的意思是"把标准错误的去处，也指向标准输出当前所去的地方"，于是两股流汇进同一个文件。

### 通配符 `*` `?`

让 shell 帮你展开一批文件名：

```bash
rm *.tmp          # 删掉所有 .tmp 结尾的
ls model_?.gguf   # ? 匹配任意单个字符
```

**关键点**：通配符是 **shell** 在命令执行前就展开的，不是命令自己处理的。`rm *.tmp` 实际变成 `rm a.tmp b.tmp c.tmp` 再交给 `rm`。

### 引号 `'` `"` `\`

用来**取消特殊含义**，把一串字符原样当文本：

```bash
echo "今天花了 $5"       # 双引号：$ 仍会被解释，危险
echo '今天花了 $5'       # 单引号：$ 原样输出，安全
touch "my file.txt"      # 路径里有空格，必须用引号包起来
echo \$HOME              # 反斜杠转义单个字符
```

粗略规则：**想原样，用单引号**。

## 一条命令的一生

把上面的东西全用上，看一条复合命令：

```bash
ls -lh /srv/models/*.gguf | grep Qwen > found.txt 2>&1
```

它按这个顺序发生：

1. **shell 先展开通配符**：`/srv/models/*.gguf` 变成实际存在的几个文件名。
2. **执行 `ls -lh`**：长格式、可读单位，列出这些文件。
3. **管道把结果交给 `grep Qwen`**：只留下名字里含 Qwen 的行。
4. **`>` 把剩下的写进 `found.txt`**（覆盖）。
5. **`2>&1` 把过程中任何报错也一并写进去**。

屏幕上看不到任何东西——因为输出全被改道进了文件。想看结果得 `cat found.txt`。

## 不会就查

不用背。Linux 自带说明书：

| 命令 | 作用 |
|---|---|
| `man ls` | 最权威的手册，`q` 退出，`/关键词` 搜索 |
| `ls --help` | 快速看选项列表，比 man 短 |
| `type ls` | 这个 `ls` 到底是什么（内建命令？别名？程序？） |
| `which cmake` | 它在哪个路径下 |

再加两个键盘功夫，效率翻倍：

- **Tab 补全**：敲前半段按 Tab，自动补全命令名和文件名，还能帮你发现拼错。
- **Ctrl + R**：搜索历史命令，敲过的东西不用重打。

## 常见坑

- **空格是分隔符**。`my file.txt` 是两个参数，`"my file.txt"` 才是一个。
- **`>` 会无情覆盖**。想追加用 `>>`。覆盖了没有回收站。
- **通配符没匹配到时，会原样传给命令**。`rm *.tmp` 没有 `.tmp` 文件时，可能变成要删一个叫 `*.tmp` 的文件。
- **Linux 区分大小写**。`File` 和 `file` 是两个不同的东西，`-l` 和 `-L` 常常也是。
- **短选项合并有前提**。`-lh` 等于 `-l -h`，但如果某个选项要跟值（比如 `-c 32768`），它就不能随便并进一串里。
- **`--` 之后全是参数**。文件名以 `-` 开头时（比如 `-file`），用 `--` 隔开，免得被当成选项。
