# GitHub 笔记

> 代码往哪放、改动怎么留痕、做好的东西怎么发出去。和命令行一样，是每次开发都要踩到的地基。

## 为什么单独开一个板块

[Linux 基础](/linux/) 管本机：文件在哪、命令怎么敲、进程还在不在跑。GitHub 管代码的去处：版本怎么存、改动怎么留痕、写好的东西怎么发布出去。两件事合起来，地基才算铺平。

笔记站自己从零到上线，正好把这套流程完整走了一遍：

```text
建仓库  →  提交  →  推送  →  Actions 构建  →  Pages 发布
```

每一步都有容易踩的地方：建仓库时多勾一个初始化选项，本地历史就被搅乱；Pages 的 Source 忘选，推了也不出站点；代理没开，push 直接卡在门口。这些坑散在对话里查一次忘一次，索性立个板块收着。

## 一条主线

```text
工作区            暂存区            本地历史          远端仓库          网站
  │                 │                │                │                │
  ├─── git add ────►│                │                │                │
  │                 ├── git commit ─►│                │                │
  │                 │                ├─── git push ──►│                │
  │                 │                │                ├── Actions ────►│
```

从左往右：文件被选中、被记成一次提交、被推上 GitHub、被 Actions 构建成站点、被 Pages 发布出去。每一步在哪、出了事去哪查，下面分开讲。

## 地图

| 块 | 解决什么 | 入口 |
|---|---|---|
| 仓库 | 代码的家怎么建，本地和远端怎么接上 | [仓库](/github/repository) |
| 提交 | 一次改动怎么留成一条能读懂的历史 | [提交](/github/commit) |
| 部署 | 推上去之后，怎么自动变成网站 | [部署](/github/pages-actions) |
| 认证 | 本地用什么身份推代码，不通时查哪里 | [认证](/github/auth) |
| 协作 | 多人怎么在同一个仓库里各干各的 | 待填 |
