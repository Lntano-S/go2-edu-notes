# 仓库

## 它是什么

一个 Git 仓库 = 一个普通目录 + 藏在里面的 `.git`。`.git` 装的是这个目录的全部历史：每一次提交、每一条分支、每一个远端地址。

放在你电脑上的叫**本地仓库**，放在 GitHub 上的叫**远端仓库**。两边内容不必一样：`push` 把本地的新提交送上去，`pull` 把远端的新提交拿下来。

## 建一个远端仓库

GitHub 网页上点 New repository，真正要做的决定就三个：

| 决定 | 怎么定 |
|---|---|
| 名字 | 它决定了默认的 Pages 地址，起之前想好 |
| 可见性 | Public 免费开 Pages；Private 要 Pro |
| 初始化选项 | **本地已有历史时，一个都别勾** |

第三个最容易踩。README、.gitignore、license 这三个勾选框会替你在远端先生成一条提交。本地若也已经攒了一串提交，两边就从不同的起点各长各的，之后 `push` 会因为历史不相关被拒。

什么时候该勾？**远端从零开始、本地还没建仓库**的时候。本地要是已经 `git init` 过，就留空。

## 把本地和远端接上

```bash
git remote add origin <仓库地址>   # 给远端起个名字，惯例叫 origin
git remote -v                     # 确认挂上了
git branch -M main                # 分支名改成 main
git push -u origin main           # 第一次推，-u 记住本地分支和远端的对应
```

`origin` 只是个名字，指代"那个远端地址"。一个本地仓库可以挂多个远端，只是九成时候只有一个，所以直接叫 origin。

## 常见坑

- **push 被拒，提示 non-fast-forward 或历史不相关**。远端有你本地没有的提交。轻的情况 `git pull --rebase` 后重推；重的情况两边历史各长各的，只能强推（`--force`，会盖掉远端）或者推倒重来。从源头避开它的办法，就是建仓库时别勾初始化。
- **origin 已经存在**。这时不是 `add` 而是 `set-url`：`git remote set-url origin <新地址>`。
- **用户名大小写**。GitHub 认用户名不区分大小写，但 Pages 域名一律小写。站点常量里 `SITE_URL` 用全小写，就是这个原因。
- **仓库名一改，Pages 地址跟着变**。`BASE`、`SITE_URL` 都得同步改，否则站内资源全 404。
